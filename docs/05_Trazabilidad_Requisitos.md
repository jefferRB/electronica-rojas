# Trazabilidad de requisitos críticos

- **Documento:** complemento de ER-BR-001 y ER-FS-001 · versión 1.0 · 28 de septiembre de 2026
- **Responsable:** Jefferson Rojas Brizuela

Solo las reglas cuyo incumplimiento dañaría datos, dinero, custodia o privacidad. Para cada una: regla de negocio
→ requisito funcional → dónde se aplica → qué la respalda en PostgreSQL → la prueba que lo demuestra. Rutas
relativas a `backend/src/main/java/dev/jeffrojas/electronicarojas/` (código),
`backend/src/main/resources/db/migration/` (SQL) y `backend/src/test/java/dev/jeffrojas/electronicarojas/`
(pruebas). Todas las reglas siguen en estado `PROPOSED` (ER-BR-001 §0): la evidencia demuestra la
implementación, no la validación del negocio.

## Cómo reproducir la evidencia

```powershell
cd backend
.\mvnw.cmd test                                   # todas (Testcontainers + Docker Engine)
.\mvnw.cmd test "-Dtest=InventoryConcurrencyIntegrationTests,VisitConcurrencyIntegrationTests"
.\mvnw.cmd test "-DexcludedGroups=integration"    # reglas puras y web, sin Docker
```

## Mantenimiento

Una fila se actualiza cuando cambia la regla, su implementación, su restricción o la prueba que la respalda. Si
una prueba citada se renombra o elimina, la fila cambia en el mismo commit.
